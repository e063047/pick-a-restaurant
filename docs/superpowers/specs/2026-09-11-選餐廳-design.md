# 選餐廳程式 — 設計文件

日期：2026-09-11

## 目的

讓使用者輸入距離、葷素偏好、用餐日期時間，從附近餐廳中隨機抽出 10 間候選，
再用轉盤隨機抽出最終要去的餐廳，並提供 Google 地圖連結供導航/查看評論/訂位。
整個程式必須完全免費，部署在雲端讓知道連結的人都能使用。

## 關鍵限制與決策

- **不使用 Google Places/Maps API 做搜尋**：該 API 需綁定信用卡且有機會超額產生費用，
  不符合「完全免費」的硬性需求。改用 **OpenStreetMap（Overpass API）** 作為免費資料來源。
- **不需要「人均價位」與「Google 評價星等」篩選**：OSM 沒有這類資料，拿掉此需求，
  只保留距離、葷素、營業時間三項篩選。
- **不需要帳號系統或歷史紀錄**：完全匿名、單次使用，不存個資、不需資料庫。
- **不使用前端框架**：純 HTML/CSS/JavaScript，無 build 流程。

以上決策使整個系統可以是**純前端靜態網頁**，無需後端、無需 API Key、無需資料庫。

## 架構總覽

```
使用者瀏覽器
  1. 取得使用者目前位置（Geolocation API，被拒絕時可手動輸入地址）
  2. 使用者輸入條件：距離 / 葷素 / 用餐日期時間
  3. 直接呼叫 Overpass API 查詢範圍內餐廳資料（OSM，免費、支援瀏覽器直接查詢）
  4. 前端 JS 過濾：用 opening_hours.js 解析營業時間是否符合
  5. 隨機抽最多 10 間 → 畫成 Canvas 轉盤
  6. 使用者轉動轉盤 → 抽出 1 間
  7. 顯示該店資訊 + Google 地圖連結（純網址組合，不呼叫 Google API）
```

單一靜態網站（`index.html` + `style.css` + `app.js`），部署到 GitHub Pages。

## 資料來源與篩選邏輯

### 距離與地點

- 用 `navigator.geolocation` 取得使用者座標；使用者拒絕授權時，改用 OSM
  Nominatim（免費、無需 API Key）做地址轉座標，或允許在地圖上點選位置。
- 使用者從常見選項中選擇距離範圍：500m / 1km / 3km / 5km。
- 用 Overpass API 查詢範圍內 `amenity=restaurant`（可加 `fast_food`、`cafe`）
  的店家，取得名稱、座標、`cuisine`、`diet:*`、`opening_hours` 等標籤。

### 葷素篩選

- 「全部」：不篩選。
- 「素食」：只保留明確標註 `diet:vegetarian=yes` 或 `diet:vegan=yes` 的店
  （較保守，避免誤推薦葷食餐廳給素食者，代價是可選店家數量較少）。
- 「葷食」：排除上述明確標註素食的店，其餘（含未標註的店）都算可選。

### 用餐日期時間篩選

- 使用者選擇用餐日期與時間。
- 用開源函式庫 `opening_hours.js`（MIT 授權，CDN 載入）解析每間店的
  `opening_hours` 標籤，判斷指定時段是否營業。
- **沒有標註 `opening_hours` 的店：予以保留**（不因缺資料而排除），
  在結果中標示「營業時間未知」提醒使用者自行確認。
- 只有明確標註了 `opening_hours`、且判斷該時段為「休息中」的店才會被排除。

### 結果數量

- 篩選後的候選店家隨機抽樣最多 10 間（而非固定取前 10 筆，避免每次結果重複）。
- 不到 10 間就用實際數量產生轉盤；一間都沒有時顯示提示訊息，
  建議使用者放寬條件（例如擴大距離、改選「全部」而非「素食」）。

## 轉盤 UI 與結果呈現

### 轉盤

- 用 HTML5 Canvas 畫出扇形轉盤，最多 10 個扇形，各自標上餐廳名稱
  （名稱過長時自動縮小字體或截斷）。
- 使用者點擊「轉動」按鈕，用 JS 計算隨機停止角度，搭配 CSS/JS 動畫做出
  3〜5 秒、有煞車減速效果的旋轉，最終停在隨機一個扇形上。

### 結果卡片

- 轉完後顯示中獎餐廳的名稱、地址、（若有）電話、營業時間狀態、素食標註。
- 提供「在 Google 地圖開啟」按鈕，連結格式：
  `https://www.google.com/maps/search/?api=1&query=店名+緯度,經度`
  點擊後直接跳轉 Google 地圖 App 或網頁版，使用者可自行導航、看評論、訂位。
  此連結純粹是網址組合，不需呼叫任何 Google API。

## 錯誤處理與邊界情況

- **拒絕定位權限**：提示使用者手動輸入地址，或在地圖上點選位置
  （用免費的 Nominatim 做地址轉座標）。
- **Overpass API 逾時/失敗**：公開 Overpass 節點有時會忙碌或限流，
  設計自動重試並切換備用節點（例如 `overpass-api.de` 失敗後改用
  `overpass.kumi.systems`），並顯示「查詢中，可能需要幾秒鐘」提示。
- **查無結果**：提示使用者放寬篩選條件。
- **手機瀏覽器相容性**：需在手機 Safari/Chrome 測試轉盤觸控操作與 GPS 定位。

## 部署方式

- 使用 **GitHub Pages**：建立 public repo，放入 `index.html`、`style.css`、
  `app.js`，開啟 GitHub Pages 設定，即可得到免費網址
  `https://<帳號>.github.io/<repo>/`，任何知道連結的人都能使用。
- 之後更新程式只需 `git push`，無額外部署流程。
- 未來如需更快載入速度或自訂網域，可再換成 Cloudflare Pages。

## 測試方式

- 不使用自動化測試框架（規模小、單頁應用），採手動測試涵蓋：
  - 不同距離範圍
  - 葷素篩選（含「素食但未標註」的店是否正確被排除）
  - 不同用餐時間點（含打烊時段、未標註營業時間的店）
  - 定位失敗與手動輸入地址
  - 查無結果的提示
  - 轉盤動畫與隨機性
  - Google 地圖連結是否正確跳轉
